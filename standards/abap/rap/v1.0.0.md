# SAP ABAP Cloud & RAP (RESTful Application Programming) Architecture Reference Standard
> **Standard Version:** `v1.0.0`
> **Target Scope:** SAP BTP ABAP Environment (Steampunk), SAP S/4HANA Cloud, Private Cloud, and On-Premise 2020+.
> **Core Benchmark:** Clean ABAP, ABAP Cloud Language Version, RAP BO Modeling, and Modern CDS Views.

---

## 1. Quick Identity & Stack Specification

| Attribute | Standard Value | Description / Rule |
| :--- | :--- | :--- |
| **Language Version** | **ABAP Cloud** (`LanguageVersion = 5`) | Cloud-ready, clean core, only released SAP APIs (`C1` contracts). No direct table mods |
| **Model Paradigm** | **RAP (RESTful Application Programming)** | Business Object (BO) driven architecture using CDS View Entities & Behavior Definitions |
| **Naming Prefix** | `Z` / `Y` or corporate namespace `/UPPER/` | Strictly structured prefixes per object type (e.g. `ZI_*` for interface, `ZC_*` for consumption) |
| **Database Access** | Read via CDS, Write via EML (Entity Manipulation Language) | No direct `INSERT / UPDATE / DELETE` in ABAP business logic; all mutations via `MODIFY ENTITIES` |
| **Protocol Exposure** | OData V4 (preferred) / OData V2 | Exposed via Service Definition (`SRVD`) and Service Binding (`SRVB`) |

## 2. Layering & Naming Conventions

Compliant ABAP RAP developments must strictly distinguish between **Data Definition**, **Behavior**, and **Projection/Consumption**:

```text
Object Type                         Naming Pattern               Example
-------------------------------------------------------------------------------------------------
Basic / Interface CDS Entity        ZI_<Entity>                  ZI_CustomerMaster
Consumption / Projection CDS Entity ZC_<Entity>                  ZC_CustomerMaster
Behavior Definition (Root Interface)ZI_<Entity>                  ZI_CustomerMaster (bdef)
Behavior Definition (Projection)    ZC_<Entity>                  ZC_CustomerMaster (bdef)
Behavior Pool (Implementation Class)ZBP_I_<Entity> / ZBP_C_*     ZBP_I_CustomerMaster
Service Definition                  ZUI_<Entity>_O4 (or _O2)     ZUI_CustomerMaster_O4
Service Binding                     ZUI_<Entity>_O4_BIND         ZUI_CustomerMaster_O4_BIND
Data Definition Table (if custom)   Z<entity>_TAB                ZCUSTOMER_TAB
```

## 3. Core Coding Rules for ABAP Cloud

1. **Clean Core & Released APIs Only:**
   - Obsolete statements (`MOVE`, `WRITE`, `FORM / ENDFORM`, `TABLES`) are strictly prohibited.
   - Use modern ABAP expressions: `VALUE #( ... )`, `CORRESPONDING #( ... )`, `COND #( ... )`.
2. **Behavior Implementation (Local Classes in Behavior Pools):**
   - Business validations must run in `VALIDATION <name> ON SAVE`.
   - Field determination and defaults must run in `DETERMINATION <name> ON MODIFY`.
   - Access control checks must run in `AUTHORIZATION: GLOBAL / INSTANCE`.
3. **Error Handling via `%MSG` / `%FAIL`:**
   - Never use classic exceptions or `MESSAGE e001(...)` stopping execution abruptly.
   - Return messages through `reported-<entity>` using message classes inheriting from `if_abap_behv_message`.
4. **Draft Enablement:**
   - For all Fiori applications requiring stateful user editing, implement `with draft;` in the Behavior Definition with dedicated draft table `Z<entity>_D`.

## 4. AI Agent Audit Checklist for ABAP RAP Projects

- [ ] ABAP Cloud Language Version enabled (no classic unreleased SAP function modules).
- [ ] Interface views (`ZI_*`) decoupled from Consumption views (`ZC_*`).
- [ ] Mutations dispatched exclusively via EML (`MODIFY ENTITIES OF ...`).
- [ ] Business logic isolated in local handler classes within `ZBP_I_*`.
- [ ] No hardcoded text literals; all user messages reference SE91 Message Classes.
