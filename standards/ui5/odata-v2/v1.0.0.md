# SAPUI5 Project Architecture & Code Quality Reference Standard
> **Document Role:** Direct Prompt & Evaluation Feed for AI Agents auditing and reviewing SAPUI5 projects.
> **Reference Benchmark:** `intl-customer-master-data-ui5` (`com.agrosuper.intlcustomermasterdata`)

## 1. Quick Identity & Stack Specification

| Attribute | Standard Value | Description / Rule |
| :--- | :--- | :--- |
| **Namespace / App ID** | `com.<company>.<appname>` (e.g. `com.agrosuper.intlcustomermasterdata`) | Declared in `manifest.json`, `ui5.yaml`, and module paths |
| **UI5 Core Version** | `>= 1.141.1` (or `>= 1.120.x`) | Declared in `manifest.json` under `sap.ui5.dependencies.minUI5Version` |
| **Language** | **JavaScript (ES6+)** | No TypeScript. Use modern ES6+ features (`const`, `let`, `async/await`, arrow functions, destructuring) |
| **Theme** | `sap_horizon` | Declared in `ui5.yaml` and `index.html` bootstrap |
| **Async View Loading** | Mandatory | `sap.ui.core.IAsyncContentCreation` interface in `Component.js` + `"async": true` in routing & rootView |
| **Backend Integration** | OData V2 (`sap.ui.model.odata.v2.ODataModel`) | Connected via `fiori-tools-proxy` in `ui5.yaml` to CAP / SAP service |
| **ESLint Status** | Non-configured by Fiori Tools | No `.eslintrc` file in repo; enforce rules via this guideline |
| **Security / Auth** | SAP Fiori Launchpad Shell + Custom RBAC | `sap.ushell.Container.getUser().getEmail()` + `x-user-id` header on OData requests |

## 3. Naming Conventions & Rules

An auditing agent must check every file and identifier against these naming rules:

### 3.1. Files & Folders
- **Controllers:** `PascalCase.controller.js` (e.g., `Main.controller.js`, `BaseController.js`).
- **Views:** `PascalCase.view.xml` (e.g., `Main.view.xml`, `App.view.xml`).
- **Table Fragments:** Located in `webapp/view/fragment/table/` with pattern `tbl<Entity>Dlg.fragment.xml` or `tbl<Entity>.fragment.xml` (e.g., `tblUsersDlg.fragment.xml`, `tblCountryDlg.fragment.xml`).
- **Create/Edit Dialog Fragments:** Located in `webapp/view/fragment/create/` with pattern `Create<Entity>.fragment.xml` (e.g., `CreateUsers.fragment.xml`, `CreateCountry.fragment.xml`).
- **Utility / Model Modules:** `PascalCase.js` for classes/singletons (`Utilities.js`), `camelCase.js` for modules/factories (`formatter.js`, `models.js`).

### 3.2. Variable Naming (SAP Hungarian Notation)
Strict adherence to SAP Hungarian Notation is enforced across the codebase:
- `o` -> Object (`oModel`, `oEvent`, `oData`, `oDialog`, `oContext`, `oSource`, `oFilter`, `oBinding`)
- `s` -> String (`sPath`, `sEntity`, `sProperty`, `sFragmentName`, `sCode`, `sQuery`, `sDetail`, `sIdTable`)
- `a` -> Array (`aFilters`, `aValidated`, `aEmptyFields`, `aFormContainers`, `aRoles`, `aItems`)
- `b` -> Boolean (`bCreate`, `bLocale`, `bHasEmptyFields`, `bIsAuthorized`, `bEnabled`)
- `fn` -> Function (`fnAdicional`, `fnCallback`, `fnSuccess`)
- `m` -> Map / Metadata Dictionary (`mAggregations`, `mProperties`, `mParameters`)

### 3.3. Method & Function Naming
- **UI Event Handlers:** Must start with prefix `on` followed by `CamelCase` describing the action:
  - Lifecycle: `onInit`, `onExit`, `onBeforeRendering`.
  - User interactions: `onOpenDialog`, `onCloseDlg`, `onSave`, `onConfirmDelete`, `onSearch`, `onHandleEdit`, `onLanguageSelected`, `onUpperCase`.
- **Private / Internal Controller Functions:** Prefixed with underscore `_` (e.g. `_validateUserPermissions`, `_fragments`).
- **Service & Utility Functions:** Descriptive `camelCase` verbs (e.g. `createService`, `readService`, `validateAndPrepareData`, `cleanValueState`, `isJSONValid`).
- **Model / Data Accessors:** Prefixed with `get` / `set` (e.g. `getRouter`, `getModel`, `setModel`, `getResourceBundle`, `getCountries`, `getCurrencies`).

## 4. Reusable Modules & Functional API Catalog

### 4.1. `webapp/controller/BaseController.js`
Inherited by every view controller using `Base.extend(...)`:
- `getRouter()`: Convenience accessor returning `sap.ui.core.UIComponent.getRouterFor(this)`.
- `getModel(sName)`: Accessor for Component-level models (`this.getOwnerComponent().getModel(sName)`).
- `setModel(oModel, sName)`: Setter for Component-level models.
- `getResourceBundle()`: Returns `this.getOwnerComponent().getModel("i18n").getResourceBundle()`.
- `showMessage(sType, sMessage, sDetail)`: Promise-wrapped modal message dispatcher supporting `"Error"`, `"Success"`, `"Warning"`, and default Alert via `sap.m.MessageBox`.
- `onOpenDlg(sFragmentName, fnAdicional)`:
  - Dynamically loads XML fragment from `com.agrosuper.intlcustomermasterdata.view.fragment.create.<sFragmentName>`.
  - Caches dialog promise instance on controller instance (`that[sFragmentName]`).
  - Automatically runs `Utilities.cleanValueState(...)` on the dialog's form aggregations before opening.
  - Executes optional callback `fnAdicional()` and opens dialog `oDialog.open()`.
- `onCloseDlg(sFragmentName)`: Closes the cached dialog instance via `.then(oFragment => oFragment.close())`.

### 4.2. `webapp/utils/Utilities.js`
Singleton object initialized once in `App.controller.js` with the primary OData model (`Utilities.init(this.getModel())`). Exposes:
- `create(sPath, oData)`: Returns `Promise` resolving to created OData payload or rejecting with `oError`.
- `createService(oModel, oData, sEntity)`: Generic Promise-wrapped `oModel.create("/" + sEntity, oData)`.
- `read(sPath)`: Returns `Promise` executing `that.oServiceModel.read(sPath)`.
- `readService(oModel, sEntity, aFilters, oParameters)`: Parameterized read with `urlParameters` and `filters`.
- `update(sPath, oDataToUpdate)`: Returns `Promise` executing `that.oServiceModel.update(sPath, oDataToUpdate)`.
- `remove(sPath)`: Returns `Promise` executing `that.oServiceModel.remove(sPath)`.
- `validateAndPrepareData(oEvent, localmodel, property)`:
  - Discovers the `sap.ui.layout.form.Form` inside the dialog container aggregations.
  - Calls `this.validateFields(mAggregations)`.
  - If validation passes, clones and returns the target payload from `localmodel.getProperty("/" + property)`.
  - If invalid, returns `false`.
- `validateFields(mAggregations)`:
  - Inspects all visible form elements.
  - Checks control instances:
    - `sap.m.ComboBox` / `sap.m.Select`: `selectedKey !== ""` -> sets `ValueState.Error` / `None`.
    - `sap.m.MultiComboBox`: `selectedKeys.length > 0`.
    - `sap.m.Input` / `sap.ui.unified.FileUploader`: `value.trim() !== ""`.
    - `sap.m.DateRangeSelection`: `dateValue !== null`.
  - Returns `true` if any field contains an `Error`.
- `cleanValueState(mAggregations)`: Resets all controls supporting `setValueState` to `"None"`.

### 4.3. `webapp/model/formatter.js`
- `formatRequestCreditLineState(bParameter)`: Returns `"Success"` (true) or `"Error"` (false).
- `isActive(value)`: Checks boolean or `"true"` string, returning `"Success"` or `"Error"` for `sap.m.ObjectStatus`.

### 4.4. `webapp/model/localModel.json`
Acts as the central UI state schema:
- `create`: Dict with keys per entity (`users`, `countryApprovers`, `countries`, etc.) storing temporary form state.
- `config`: Maps entity names to their array of active property fields (e.g. `"users": ["code", "userId", "firstName", "lastName", "email", "isActive", "salesOffice_code", "userRoles"]`).
- `isEdit`: Global boolean indicating whether the active dialog is in Create (`false`) or Edit (`true`) mode.

## 5. Coding Style, Syntax & Patterns

### 5.1. Module Definition Pattern
Always declare dependencies via `sap.ui.define`.
Always specify `"use strict";` immediately inside the factory function:
```javascript
sap.ui.define([
    "com/agrosuper/intlcustomermasterdata/controller/BaseController",
    "sap/ui/core/Fragment",
    "sap/m/MessageBox",
    "sap/m/MessageToast",
    "sap/ui/model/Filter",
    "sap/ui/model/FilterOperator",
    "com/agrosuper/intlcustomermasterdata/utils/Utilities",
    "com/agrosuper/intlcustomermasterdata/model/formatter"
], function (Base, Fragment, MessageBox, MessageToast, Filter, FilterOperator, Utilities, formatter) {
    "use strict";

    return Base.extend("com.agrosuper.intlcustomermasterdata.controller.Main", {
        formatter: formatter,
        // ...
    });
});
```

### 5.2. Asynchronous Programming & OData Operations
- Use `async/await` for controller actions (`onSave`, `executeDelete`, `getCountries`).
- Wrap OData V2 callback methods (`success`, `error`) inside native `Promise` wrappers (as in `Utilities.js`).
- Never freeze the UI; always refresh target table bindings upon successful mutation:
  ```javascript
  sIdTable && this.byId(sIdTable).getModel().refresh(true);
  ```

### 5.3. Error Handling Pattern
Standardized `try / catch` block inspecting OData response formats:
```javascript
try {
    await Utilities.create(sPath, oData);
    MessageBox.success(i18n.getText(successKey, [idOrCode]));
} catch (error) {
    const responseText = error?.responseText ?? 'Error desconocido';
    const isJSON = that.isJSONValid(responseText);
    const msg = isJSON ? JSON.parse(responseText).error.message.value : responseText;
    MessageBox.error(msg);
}
```

### 5.4. Internationalization (i18n) & Dynamic Language Switching
- No hardcoded strings in Views or Controllers.
- All labels, dialog titles, table headers, confirm prompts, and error messages must use `{i18n>key}` or `i18n.getText("key", [param1])`.
- Multi-language support must include `es` (Spanish), `en` (English), `ja` (Japanese), `zh` (Chinese).
- Changing languages re-instantiates the OData model with updated `Accept-Language` headers and refreshes the binding.

### 5.5. Security & Context Propagation
- In `Component.js`, read the logged-in user email:
  ```javascript
  const sEmail = sap.ushell.Container.getUser().getEmail();
  ```
- Propagate user email in default OData model headers:
  ```javascript
  mainModel.setHeaders({
      "x-user-id": sEmail
  });
  ```
- Enforce Role-Based Access Control (RBAC):
  Validate `aRoles` against `aValidRoles = ["TEST_USER", "ADMIN", "MASTER_DATA", "GVI"]`.
  If unauthorized, invoke `this.getRouter().navTo("notAuthorized", {}, true)`.

## 6. ESLint & Static Analysis Rules (Synthetic Ruleset)

Because the project was initialized without an active `.eslintrc` file, an auditing agent must evaluate JavaScript code against the following standard ESLint rules tailored for SAPUI5 ES6:

```json
{
  "env": {
    "browser": true,
    "es6": true
  },
  "rules": {
    "no-undef": "error",
    "no-unused-vars": ["warn", { "argsIgnorePattern": "^_" }],
    "no-redeclare": "error",
    "no-console": ["warn", { "allow": ["warn", "error"] }],
    "prefer-const": "warn",
    "no-var": "error",
    "eqeqeq": ["error", "always", { "null": "ignore" }],
    "curly": ["error", "all"],
    "semi": ["error", "always"],
    "quotes": ["warn", "single", { "avoidEscape": true, "allowTemplateLiterals": true }],
    "sap-no-global-variable": "warn",
    "valid-jsdoc": "warn"
  }
}
```

### Known Technical Debt / Antipatterns in Reference to Avoid:
1. **Typo in XML root tag:** In `webapp/view/Main.view.xml` line 189: `</Page>a` (stray character after closing tag). **Flag as error.**
2. **Implicit loose comparison:** Use `===` instead of `==` (e.g. `sEntity === 'CountryApprovers'`).
3. **Module-level variable leaks:** Relying on top-level `let that, localmodel, i18n;` outside the Controller definition can cause cross-instance pollution if the controller is instantiated multiple times. Prefer storing instances on `this` (`this._oLocalModel`, `this._oResourceBundle`).
4. **Missing trailing semicolons:** Consistently terminate statements with semicolons.

## 7. AI Agent Audit Checklist for Other Projects

When an AI agent is instructed to audit a UI5 repository against this reference, it must evaluate each category and score compliance (PASS / FAIL / WARNING):

1. **Architecture & Folder Structure**
   - [ ] Contains `webapp/` with `controller/`, `view/`, `view/fragment/table/`, `view/fragment/create/`, `model/`, `utils/`, `i18n/`.
   - [ ] Contains `BaseController.js` extended by functional controllers.
   - [ ] Contains `Utilities.js` encapsulating CRUD and form validation.
   - [ ] Contains `localModel.json` modeling transient entity payloads and configurations.

2. **Naming Conventions**
   - [ ] Controllers use `PascalCase.controller.js`.
   - [ ] Table fragments use `tbl<Entity>Dlg.fragment.xml`.
   - [ ] Create dialog fragments use `Create<Entity>.fragment.xml`.
   - [ ] Event handlers use `on<Action>`.
   - [ ] Private methods use `_<method>`.
   - [ ] Hungarian notation used for variables (`oData`, `sPath`, `aItems`, `bFlag`).

3. **Models & Data Binding**
   - [ ] OData V2 configured in `manifest.json` as default datasource.
   - [ ] Multi-language `i18n` bundles configured with supportedLocales.
   - [ ] Model `localModel` loaded from `model/localModel.json`.
   - [ ] `device` model configured using `sap/ui/Device`.

4. **Security & Authorization**
   - [ ] `Component.js` extracts user identity from `sap.ushell.Container`.
   - [ ] Request header `x-user-id` set on OData model.
   - [ ] Role validation checks against permitted roles before routing to main view.
   - [ ] Route `notAuthorized` and target `TargetNotAuthorized` implemented.

5. **Code Quality & Error Handling**
   - [ ] `"use strict";` declared in every JS file.
   - [ ] CRUD operations wrapped in Promises and handled with `async/await` + `try/catch`.
   - [ ] Error messages parsed from OData JSON responses and displayed via `MessageBox.error`.
   - [ ] Form controls validated with `ValueState` feedback before dispatching OData payload.
   - [ ] Zero hardcoded user-facing strings; all bound to `i18n`.
